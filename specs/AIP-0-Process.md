# AIP-0: AiXin Improvement Proposal Process

- **AIP:** 0
- **Title:** AIP Process and Editors
- **Status:** Draft
- **Type:** Process
- **Created:** 2026-07-24
- **Requires:** —

## Abstract

This document describes the process by which the AiXin Protocol evolves.
It is modeled on BIP-2, EIP-1, and RFC 2026.

## Motivation

An open protocol requires a documented, neutral change process, or vendors
will (rightly) refuse to build on it.

## Specification

### AIP Types

- **Standards Track** — normative protocol changes (e.g. AIP-1 SIP, AIP-2 TOP).
- **Process** — meta-changes to the AIP process, governance, tooling.
- **Informational** — non-normative guidance.

### Status Lifecycle

`Draft → Review → Last Call (14 days) → Final` (or `Withdrawn` / `Superseded`).

### Editors

- Minimum 3, maximum 7. At least one editor MUST NOT be employed by the
  AiXin Foundation or any AiXin-affiliated commercial entity.
- Editors merge PRs when the AIP meets structural requirements. Editors do
  NOT gate on technical opinion.

### Required Sections

Every AIP MUST contain: Abstract, Motivation, Specification, Rationale,
Backwards Compatibility, Reference Implementation, Security Considerations,
Copyright (must waive to CC0 or Apache-2.0).

### Normative Language

AIPs use RFC 2119 terms (MUST, SHOULD, MAY) in ALL CAPS.
